# Validate rules

Read by SKILL.md step 7 after measure.py. Report each problem as `rule <id>: <problem>`, one entry per problem. Each rule says whether measure.py checks it (script) or you check it by reading (judged); trust a script result, and judge only the judged rules. measure.py prints a `failures:` line of rule ids and a `warnings:` line; a warning never blocks install. `{{ SKILL_ROOT }}/scripts/test_scripts.py` is the self-test for measure.py, stage.py and eval.py; run it only when changing those scripts.

## Frontmatter

- Rule A1, required keys (script). `name` is kebab-case and at most 64 characters, `description` is non-empty and at most 1,024 characters, `tools` lists at least one tool (only `worker` and its generated variants, whose name equals the file stem, may omit it and so inherit every tool, with `disallowedTools` as the control), and `metadata.version` is present in semver form `X.Y.Z`, such as `1.0.0`; a missing or malformed version fails with a `version_error:` line.
- Rule A2, no model or effort (script). A `model` or `effort` key fails, because the model and effort are chosen per spawn, not per agent. A key other than `name`, `description`, `tools`, `disallowedTools` and `metadata` is a warning.
- Rule A3, no spawning (script). `Agent` (or its older name `Task`) in `tools` fails unless measure.py runs with `--allow-agent`, which is passed only when the user asked for the tool by name.
- Rule A10, no contradiction (script). A tool listed in both `tools` and `disallowedTools` fails.
- Rule A12, tools match the steps (judged). Every tool a workflow step names is in `tools`, and `tools` holds no tool that no step or core rule needs.

## Body

- Rule A4, sections (script). The body has exactly these H1 headings, in this order: `# Role`, `# Constraints`, `# Workflows`, `# Exception handler`.
- Rule A5, core kept verbatim (script). The core blocks `identity` and `constraints`, each between `<!-- core:begin NAME -->` and `<!-- core:end NAME -->`, are present, sit in their home section (Role, Constraints) and are byte-identical to the same blocks in `{{ SKILL_ROOT }}/assets/base/worker.md`. The constraints core is the first thing in Constraints; extending rules follow it. An agent named `scout` may omit constraints core items 1 and 2 (it holds no file or shell tool); the rest of the block must still match.
- Rule A16, report format (script). The `constraints` core says that every report is the six flat tags `<status>`, `<outcome>`, `<claims>`, `<artefacts>`, `<open>`, `<deviations>`, in that order, with `none` in an empty tag. It must contain the measure.py constants `STATUS_LINE` ("`<status>` comes first and holds one of") and `EVERY_FIELD` ("each wrapped in one flat tag"); measure.py prints `status_line_rule: yes` or fails A16. `eval.py` grades the same shape. It guards the base worker's own core, which A5 compares every fork against.
- Rule A6, workflows (script). `# Workflows` holds at least one `## <Name>` (one capitalised word, hyphens allowed), names unique. Each has a `Role:` line naming `worker`, `validator`, `reviewer` or `scout`, then the H3s `### Input`, `### Process` and `### Output` in that order. Input bullets read `* **<name>:** required - default: none - <description>` or `* **<name>:** optional - default: <value> - <description>`. Process holds numbered steps `1.` to `n.` with no gap. Output bullets read `* **<field>:** always - <what>` or `* **<field>:** when <condition> - <what>`; judged: each bullet names the relay §4 tag the field goes in, and no Output or hand-back is a field block outside the six tags.
- Rule A7, exception handler (script). `# Exception handler` holds at least one bullet.
- Rule A8, no leftovers (script). No `[[` fill-in, no `{{ CORE ... }}` line and no HTML comment remains, except the core markers.
- Rule A9, namespace (script). Every skill reference uses the in-house namespace, such as `Skill(agentville:relay)`; any reference to the old namespace fails, and measure.py lists the lines on `foreign_namespace_lines:`. A `Skill(...)` with no namespace is a warning.
- Rule A11, size (script). A file of more than 500 lines fails.
- Rule A13, role scope (judged). No workflow step breaks its role's scope: a reviewer step edits nothing and runs no tests, builds or scripts (read-only `git diff`, `git log`, `git show` and `rg` are allowed), a validator step edits no product code, and a scout step that needs the web returns `blocked` when the agent holds no web tool.
- Rule A14, hand-backs (judged). A step that needs another agent stops and hands back a `spawn-request:` naming the agent type, the role and the brief; no step spawns.
- Rule A15, relay tokens (judged). Every status the agent reports, in the Exception handler and the workflows, is one of relay §4's status tokens.
- Rule A17, scaled examples (judged). Applies to Process steps and extending rules alike. A one-line step or constraint carries no example. A step or constraint whose rule needs explanation carries one Do and one Don't. Only the task breakdown, the execution (what may run, which tools are allowed and forbidden) and the report the agent returns carry more, up to three Do and three Don't each. Every example uses real values and every Don't names its fix. An example in a shared core block suits every agent that shares it; the core is never edited to add one. Examples sit as indented sub-bullets under their step or rule, so a flush-left `Do:` never sits inside a workflow's `### Process`.
- Rule A18, injectable slots (script). An agent that uses an injectable slot (`SLOTS` in measure.py: `workspace`, `toolbelt`, `draft`, `plan`, `report`) names `Skill(agentville:context-injection)` to resolve it, then reads the resolved skill. A direct use of the default (`Skill(agentville:<slot>)`, `Skill(<slot>)`, `/agentville:<slot>` or a bare `agentville:<slot>`) fails and is listed on `slot_direct_calls:`, unless the text reads as a description of the default (the words "the plugin default" right before it with at most backticks or spaces between, as in the plugin default `Skill(agentville:<slot>)`, or `(plugin-default)` right after it, and no imperative verb, `call`, `load`, `run`, `invoke` or `use`, right before the call or before "the plugin default") or the hit is the skill id of a slot record `<slot>: <namespace>:<name> (<source>)` written without `Skill(`, with `<source>` one of `plugin-default`, `project-rules`, `project-claude-md`, `project-skill`, `user-rules`, `user-claude-md` or `user-skill`; the words elsewhere on the same line, or any other parenthesis after a call, do not exempt it. A slot use that relies on an earlier `Skill(agentville:context-injection)` load in the same file or workflow is not flagged. A slot used with no `Skill(agentville:context-injection)` anywhere fails and is listed on `slot_without_context_injection:`.

## Exemptions

Agents named `pod-lead`, `conductor` and the maintainer-only `lookout` are standalone, not a worker fork: measure.py skips A3, A5, A6 and A16 for them and runs every other rule. The `scout` core variant under A5 is the only other exemption.
